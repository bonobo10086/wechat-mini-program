# 安全部署说明

## 配置与凭据

不要提交 config.local.js、project.private.config.json、环境变量文件、真实用户记录或云控制台截图。公开示例不包含登录共享口令。

如果口令、令牌或密钥曾进入 Git 历史，应先更换或撤销。清理主分支历史不能撤回他人的克隆、本地备份或 GitHub 缓存；必要时联系 GitHub Support。仓库创建时间与提交历史是不同的元数据，历史脱敏不应伪造开发时间。

## 服务端边界

所有业务函数从 cloud.getWXContext() 读取可信调用者身份，不相信前端传入的调用者 OpenID。UserList 是管理员维护的成员名单；数据库客户端权限必须关闭，不能允许访客把自己写入名单。

业务集合限定为 MissionList、MarketList、StorageList 和 UserList。删除及星标操作检查记录所有者，仓库访问限制为本人。任务确认和商品购买不允许对自己的记录执行相应操作；积分接口限制数值范围与方向。

getOpenId 仅返回当前调用者自己的身份，不返回其他成员数据。它不是成员授权接口；login 和业务函数会额外检查成员名单。

## 尚未覆盖的风险

这是两人使用的学习原型，不是多租户生产系统。积分修改仍是独立接口，购买和任务确认尚未合并为服务端事务，也未完成幂等与限流；成员之间的恶意调用、并发竞态及断网回滚尚未完整解决。

四位匹配码不应当作为登录凭据。当前只生成记录与到期字段，没有实现加入配对、自动清理或防暴力尝试。

云数据库真实权限、订阅消息模板、平台基础库兼容性及实际云环境联调需部署者单独验证。本地模拟测试不等于渗透测试或真实部署验收。
